# 100B-200B 真空带分析：开源 MoE 为何跳过 200B 段位

> **目的**：回答用户问题 "100B / 200B 怎么设计 / 怎么 scaleup"，并解释 2026 年开源 MoE 市场为什么在 100B → 236B → 355B → 671B → 1T 之间**明显跳过 200B 段位**。
> **结论先讲**：200B 是**经济不划算 + 技术过渡区**的双重真空带。**如果非做不可，应该"100B 配方 + 部分 V3 升级"插值**，但更好的选择往往是直接跳到 300-400B。

## 2. 为什么市场跳过 200B？四个原因

### 2.1 技术原因：性能跟 100B 拉不开差距

[[18_params_vs_flops]] (Apple scaling law) + [[37_ling1t]] (Ling 1T 论文) 双重证据：
- Active params 是 capability 主驱动 (FLOPs ∝ active)
- Total params 主要拉容量上限，但**容量边际效用递减**
- 100B/12B → 200B/15B 的 active 只涨 25% → FLOPs 只涨 25% → loss 改善只有约 √1.25 - 1 = 12%

实证：
- **GLM-4.5-Air (106B/12B)** SWE-bench Verified = 53.1
- **Qwen3-235B-A22B-Thinking-2507 (235B/22B)** SWE-bench Verified = ~50（看 GLM-4.5 Figure 2）

→ **235B 用 active 翻倍但 SWE-bench 没领先**，说明 200B 段位带不来质变。

### 2.2 经济原因：训练成本翻倍但推理价格无法翻倍

| 段位 | 训练成本 (H100, 25T tokens) | 客户能接受的推理价 |
|---|---|---|
| 100B / 12B active | ~$5M | $0.5-1.0 per 1M output |
| 200B / 15B active | ~$12M | $1.0-1.5 per 1M (不能翻倍) |
| 400B / 30B active | ~$25M | $2.0-3.0 per 1M (可翻倍) |
| 671B / 37B active | ~$40M | $5-7 per 1M (V3 定价) |

→ 200B 段位**训练成本翻倍但市场价无法翻倍**（用户不会因为 active 涨 25% 就付 50% 溢价）。**ROI 比 100B 差**。

### 2.3 工程原因：EP/PP 拓扑跳档不平滑

100B 段位：
- EP = 8-16 (1-2 nodes)
- PP = 2-4
- 适合 8-16 节点集群

200B 段位：
- EP = 16-32 (2-4 nodes), **必须开 NLR**
- PP = 4-8, **必须 1F1B-overlap 或 DualPipe**
- KV cache 主导 → **必须 MLA 或重 GQA (96Q/8KV)**
- 适合 32-64 节点集群

400B+ 段位：
- EP = 32-64
- PP = 8-16
- 全部 V3 风格配置
- 适合 256+ 节点集群

→ 200B "腰部"需要的基础设施跟 400B+ 几乎一样，**多花一份 infra 工程做 50% 能力 model 不划算**。

### 2.4 战略原因：开源团队都在做 "标志性 SOTA"

| 团队 | 旗舰 | 紧凑版 |
|---|---|---|
| DeepSeek | V3 671B / R1 671B | – (没有中型版) |
| Moonshot | Kimi K2 1T | Moonlight 16B |
| Alibaba (Qwen) | Qwen3-Coder 480B | Qwen3-30B-A3B / Qwen3-Next-80B |
| Z.ai | GLM-4.5 355B | GLM-4.5-Air 106B |
| Inclusion AI | Ling-1T 1T | Ling-flash 103B / Ling-mini 16B |
| Tencent | Hunyuan-Large 389B / Turbo-S 560B | Hunyuan-A13B 80B |
| Meituan | LongCat-Flash 560B | – |
| rednote | dots.llm1 142B | – |

→ **每家都在 "100B 紧凑版" 和 "300B+ 旗舰" 之间二选一**，没人选中间。**200B 既不能当旗舰也不能当紧凑版**。

## 3. 反例分析：选了 200B 的团队后来怎么了？

### Qwen3-235B-A22B (2025-04 → 2025-12 fade)
- 2025-04 首发，benchmark 介于 GLM-4.5-Air 和 GLM-4.5 之间
- 2025-07 团队**直接发 Qwen3-Coder 480B/35B**，明显跳过 235B 继续放大
- 2025-09 团队**直接发 Qwen3-Next-80B/3B**，回到 100B 段位
- 235B 没有更新版本，**事实上被团队放弃**

### MiniMax-M2 (2025-10)
- 230B / 10B active，**active 跟 100B 段位 Ling-flash 同档**
- "230B" 本质是 total params 注水（256 expert × 大 expert FFN）
- 不是真正的"200B 旗舰"，而是 **"100B-active-class with bigger expert pool"**

→ **如果你要做 200B，请检查是不是落入这种**："活在 100B 段的 active params + 200B 段的 total params 注水"**陷阱**。

### DeepSeek-V2-236B (2024-05)
- 这是 V3 671B 的**前身**（V2 → V3 跳 2.8×）
- 2024-12 V3 发布后 V2 即被淘汰
- 是历史模型，不是"200B 是好选择"的证据

## 4. 如果你**非要做 200B**，应该怎么设计？

### Profile 200B-Lean（推荐，跟 Ling 派路线）

| 维度 | 选择 | 来源 |
|---|---|---|
| Total / Active | **220B / 13B** | 跟 Ling-flash 103B/6.1B 配方等比放大 |
| Layers | **48** | Ling-flash 32L × 1.5 (不是 2×) |
| Hidden | **4608** | 不到 5120，避免直接撞 GLM-4.5 355B 设计 |
| MoE Intermediate (expert FFN) | **1280** | Ling-flash 1024 × 1.25 |
| Attention | **GQA 36Q/4KV + QK-Norm + Partial RoPE** | Ling 系标配 |
| Head dim | **128** | Ling 全系固定 |
| Experts | **256 routed + 1 shared, K=8** | Ling 全系不变 |
| Activation Ratio | **5.9%** | 跟 Ling-flash 完全一致 |
| Routing | **sigmoid + ALF (zero-mean)** | Ling 派标配 |
| routed_scaling_factor | **2.5** | V3/Ling/GLM/dots1 共识 |
| MTP | **D=1, λ=0.1** | Ling 派 (不要用 GLM 的 0.3→0.1 schedule) |
| First-K-Dense | **2** | Ling-flash=1, Ling-1T=4，220B 段位插值 |
| QK-Norm | **是** | Ling + GLM (Air 不用，但你不是 Air 量级) |
| Optimizer | **AdamW (β1=0.9, β2=0.95)** | Ling 路线，不要 Muon |
| LR Scheduler | **WSM (N=16 checkpoint avg)** | Ling 验证最强 |
| LR | **2.2e-4** | Ling 2.61e-4 (103B) → 1.86e-4 (1T) 插值 |
| Batch | **12000** | Ling 8352 (103B) → 18144 (1T) 插值 |
| FP precision | **FP8 fine-grained quant** | Ling 1T 已证可行，220B 应没问题 |
| Tokens | **22-25T** | 与 GLM-4.5 (23T) / Ling-1T (~21T) 一致 |
| 数据 | **48% reasoning + 52% general** | Ling 路线（pre-train substage 2 比例） |

### 训练系统

| 维度 | 选择 |
|---|---|
| EP | **32** (4 nodes × 8 GPU H100) |
| PP | **6** (48 layer / 6 = 8 layer per stage) |
| TP | **2** (4608 hidden / 2304 per device) |
| DP | filling out |
| NLR M | **4** (EP 跨 4 节点必须) |
| Pipeline schedule | **Interleaved 1F1B + partial recomputation** (Ling 1T 风格，处理 MTP + First-K-Dense 异构) |
| Framework | **Megatron-LM with MoE patches** |
| 总 GPU 数 | ~384-512 H100 |
| 训练时长 | ~45-60 天 |
| 训练成本 | ~$12-18M ($3/hr × 384 GPU × 45 days × 24 hours = $11M) |

### 三个 wind tunnel 必测项

1. **L=48 是否真的够深** —— Ling-flash 32L vs GLM-4.5 92L 中间路线，没人 validate 过
2. **MTP D=1 在 13B active 下是否稳** —— 13B active 处于 D=1 / D=3 边界（[[23_mtp_investigation]] §8）
3. **WSM 在 N=16 的 checkpoint 平均下是否复刻 Ling 收益** —— Ling 用 N=32，N 减半是否影响

## 5. 更好的选择：从 100B → 直接 300-400B

如果你的诉求是 "比 100B 强"，**跳过 200B 直接做 300-400B** 在 ROI 上更划算：

### Profile 300B-Lean（替代方案 A，跟 GLM-4.5 路线）

| 维度 | 选择 |
|---|---|
| Total / Active | 320B / 28B |
| Layers | 70 (GLM-4.5 92L × 0.76) |
| Hidden | 4864 |
| Experts | 160 routed + 1 shared, K=8 (GLM 配方) |
| 估训练成本 | ~$22M |
| 估能力差距 vs 100B | **~25-30% 强**（vs 200B 的 12%） |
| ROI ratio | $22M / 28% = 79K per pct |
| **vs 200B ROI** | $14M / 12% = **117K per pct**（200B 更贵） |

### Profile 400B-Aggressive（替代方案 B，跟 V3 路线）

| 维度 | 选择 |
|---|---|
| Total / Active | 400B / 22B (Llama 4 Maverick 配方但更稀疏) |
| Layers | 64 |
| Hidden | 5120 |
| Experts | 256 routed + 1 shared, K=8 |
| MLA | **必须**（KV cache 已不可控） |
| 估训练成本 | ~$28M |
| 估能力差距 vs 100B | **~40% 强**（最强 ROI） |

## 6. 100B → 200B / 300B / 1T 三档 scaleup 决策表

> 如果你 16B 训完想 scale up，下一步该跳哪？

| 当前 | 下一步选项 | 何时选 |
|---|---|---|
| 16B | **100B** | 默认。你已经走在这条路上 |
| 100B | **200B** | **不推荐**。除非有特定客户合同要 "200B 标签" |
| 100B | **300-400B** | **推荐**。capability/cost ROI 最高 |
| 100B | **1T (Ling-1T 路线)** | 如果你团队有 256+ H100 节点能力 + 1.5 年预算 |
| 300B | 1T | 标准放大 |
| 1T | – | 当前开源天花板 |

## 7. 如果你已经决定要做 200B，最后 5 个检查项

1. **客户合同里"200B" 是 total params 还是 active params？** 如果是 total，可以用 230B/10B（Ling-flash 配方稀释）省成本
2. **是否真的需要 200B-class model 还是 100B + 更好 SFT 就够？** 大多数客户的 "200B 需求" 来自 marketing，不来自实测
3. **基础设施是 32 节点还是 64 节点？** 32 节点 EP=32 紧绷，64 节点又装不满 → 32-64 节点是 200B 的 awkward zone
4. **训练数据准备好 25T tokens 没？** 不到 22T 别开始（capacity 浪费）
5. **post-training 团队能否支撑 DFT + Evo-CoT + LPO 全套？** 200B base + 弱 SFT = 跟 100B 同效果

---

## 8. 我对 2026-2027 趋势的猜测（推测，非证据）

- **2026 H2**：200B 段位可能因 **agent workflow 客户需求**（中等推理 + 中等延迟）开始有 production 模型
- **2027**：200B "腰部" 可能被 **"100B + 长 CoT"** 路线替代（reasoning 模型不需要 200B base，需要 100B + 100K+ tokens 的 inference time compute）
- **GPT-5 / Claude 5 等 闭源** 可能就是 100B-300B active 的 sparse MoE，而不是更大

→ **战略建议**：如果你团队**只能做一个旗舰**，做 100B 紧凑版 + 1T 旗舰双款，跳过 200B。
