# GLM-4.5 / GLM-4.5-Air: Agentic, Reasoning, and Coding (ARC) Foundation Models

- **arXiv**: 2508.06471 (v1, 8 Aug 2025)
- **机构**: Zhipu AI & Tsinghua University (Z.ai / THUDM)
- **作者**: GLM-4.5 Team
- **开源**: github.com/zai-org/GLM-4.5, huggingface.co/zai-org/GLM-4.5
- **同源**: GLM-4.6 (2025-09) 架构完全相同，仅训练数据与上下文扩到 200K

## TL;DR

GLM-4.5 是 **"深 > 宽" 路线的 100B-355B 段位代表作**，与 DeepSeek-V3 / Kimi K2 的"宽 + 多专家"路线形成鲜明对照。355B/32B 用 **92 层** stack（V3 是 61 层，K2 是 61 层），并显式声明 "we reduce the width and increase its height ... deeper models exhibited better reasoning capacity"。三大独特设计：

1. **92 层 / 5120 hidden / 160 routed experts** — 唯一在 350B 段做到 L/√H ≈ 1.29 的极高瘦
2. **96 attention heads × 128 head_dim**（即 2.5× 标准比例）+ **QK-Norm** — Q 维 = 12288，每 token KV 仅 8 head
3. **Muon optimizer 训整个 base**（不是只 fine-tune），cosine 而非 WSD

ARC benchmark 上 SWE-bench Verified 64.2%, AIME 24 91.0%, TAU-Bench 70.1% — 用 V3 一半参数 / K2 三分之一参数达到接近能力。

## 核心命题

1. **Reasoning task 受益于深度，不是宽度** —— 在固定 active params 预算下，加层比加 hidden 更划算（论文 §2.1 唯一明确声明这一立场的 100B+ 团队）
2. **超量 attention heads (2.5× hidden/64) 不改 loss 但改 downstream MMLU/BBH** —— 反直觉的稳定经验性发现
3. **Muon optimizer 在 base training 阶段优于 AdamW** —— 不仅 fine-tune 阶段（Moonlight 之前的共识），整个 23T 预训也能 hold
4. **WSD scheduler 在 GLM-4.5 上反而欠拟合** —— 论文里明确否定 V3 用的 WSM/WSD 路线，选 cosine

| Activated Params | **32B** | **12B** | 37B | 32B |

| Experts Active (top-K) | **8** | **8** | 8 | 8 |
| Shared Experts | **1** | **1** | 1 | 1 |
| **QK-Norm** | **Yes** | **No** | No | No |
| Attention 类型 | **GQA + partial RoPE** | GQA + partial RoPE | MLA | MLA + MuonClip |
| L / √Hidden | **1.29** | **0.72** | 0.72 | 0.72 |

→ **GLM-4.5 是 Table 1 里 L/√H 最大的模型** —— "高瘦" 显式选择。

→ Air 反而中庸（0.72），跟 V3 / K2 持平。说明 "深 > 宽" 在 100B 段位收益不够明显，350B 段位才开始体现。

→ **96 头 / 8 KV** 是论文里反复强调的反直觉点：96×128=12288 维 Q，但只 8×128=1024 维 KV。Q/KV ratio = 12，比 V3 (128/128=1) 高一个数量级。

## 关键设计公式与超参（§2.1 + §2.4）

### Routing
- **sigmoid gate + loss-free balance** （V3 派范式，bias-based ALF, Wang et al. 2408.15664）
- bias 更新率 μ = **0.001 for first 15T tokens, 0.0 for remaining**
- Aux sequence-level balance loss **λ_aux = 0.0001**（不主，仅作 sequence 内 imbalance 防爆 hard limit）
- 没看到 routed_scaling_factor 明确数值（但 28 catalog 推断同 V3=2.5）

### MTP
- **D = 1**（同 V3，单 chain）
- **λ_MTP = 0.3 for first 15T, 0.1 remaining** —— 高于 V3 的 0.1，前期权重很重

### Optimizer 与 LR
- **Muon for all params** except embedding / bias / RMSNorm
  - Newton-Schulz iteration **N = 5**
  - momentum **μ = 0.95**
  - scaled Muon RMS = **0.2**
- LR schedule = **cosine**（明确 reject WSD：早期实验显示 WSD 在 SimpleQA/MMLU 上欠拟合"in the stable stage"）
- LR: **0 → 2.5e-4 → 2.5e-5**（warm up + cosine decay to mid-training end）
- Batch warmup: **16M → 64M tokens**（first 500B tokens 内线性涨），然后 constant
- Weight decay **0.1**, **no dropout**

### 序列长度阶段
- Pre-training: **4K**
- Mid-training: **32K**（RoPE base **10000 → 1000000**）
- Long-context extension: **131072 (128K)**
- 共 4 个阶段（Figure 3）：General 15T → Code/Reasoning 7T → Repo-level Code 500B → Synthetic Reasoning 500B → Long-context+Agent 100B
- **总 23T tokens** — 当前开源 MoE 第二多（仅次于 Qwen3 ~36T 和 Llama 4 Scout ~40T）

### 数据策略
- Quality-bucket sampling: 最高质量 bucket 在预训过 **3.2 epoch**
- SemDedup 二次去重（在 MinHash 之上）
- Mid-training 用 **best-fit packing**（防 reasoning chain 被截断），但 pre-training 用 random truncation（数据增强）

## 与 V3 / K2 的对比因果链

### 为什么 GLM 选深而 V3/K2 选宽？

| 团队 | 路线 | 公开 rationale |
|---|---|---|
| V3 / K2 | 宽 + 多专家（256-384 experts × 8 active, 61L） | inference latency 主导（layers ∝ token decode 步数） |
| **GLM-4.5** | **深 + 中等专家（160 × 8, 92L）** | **reasoning capacity（论文原文）** |
| LongCat | 极宽 + 极少层（28L / 6144 / 512 experts） | computation-communication overlap 窗口最大 |
| Qwen3-Next | 高瘦 + DeltaNet hybrid（48L / 512 experts） | 长上下文 throughput |

**因果链**：reasoning task 在 inference-time 已经会用 CoT 摊薄"每 token 多少层"的延迟成本，所以 GLM 团队判断 92L 的 sequential decode latency 不是瓶颈 —— **CoT 用户对单 token latency 不敏感，对最终质量敏感**。这是个"应用场景 → 架构选型"的反向推导。

⚠️ **风险**：如果你的目标场景是 **agent 多步骤工具调用**（每步都要快），92L 反而是劣势。GLM-4.5 在 BFCL v3 = 77.8% 已经反应过来 —— 这是论文里 agent 表现比 reasoning 弱的部分原因。

### 为什么 96 heads 而不是 64？

论文 §2.1 末尾：
> "we employ Grouped-Query Attention with partial RoPE. Furthermore, we utilize 2.5 times more attention heads (96 heads for a 5120 hidden dimension). Counterintuitively, while this increased head count does not improve training loss compared to models with fewer heads, it consistently improves performance on reasoning benchmarks such as MMLU and BBH."

**这是经验性的，不是理论推出的。** 训练 loss 不变意味着 capacity 没增加 —— 但 downstream 性能改善说明 attention head 数 ≠ capacity，而是 "attention 模式多样性"。**理论上没有人能解释为什么 96 头比 64 头好**，但 GLM 团队三个版本（4.5 / 4.5-Air / 4.6）都保留这个设计，说明经验稳定。

⚠️ Open question：96 头是不是 5120/128=40 head 的 2.4×？还是某个跟 layer 数有关的常数？数据点只有一个 (5120, 96)，没法外推。

### 为什么 QK-Norm 只在 4.5 用，4.5-Air 不用？

Table 1 显示：**GLM-4.5 = QK-Norm Yes, GLM-4.5-Air = No**。这是诡异之处。论文 §2.1 说："We also incorporate QK-Norm to stabilize the range of attention logits"。没解释为什么 Air 不用。

**我的判断**：Air 用 1 个 dense layer + 45 MoE 的浅 stack 不需要 QK-Norm 的额外稳定性；4.5 用 3 dense + 89 MoE 的深 stack 容易出 attention logit blow-up，QK-Norm 是必需。**这是 "QK-Norm 的必要性随深度上升" 的弱实证**。

## RL 训练 (§3)

- 框架：**Slime**（自研开源，github.com/THUDM/slime）
- RL 算法：**GRPO 改版**（去掉 KL 项）：`L_RL(θ) = E[1/K Σ (r(x,y_i) − r̄(x))]`
- 三大独特技巧：
  1. **Two-stage difficulty curriculum**：先 moderate，再 extreme（pass@8=0 且 pass@512>0 的极难题）
  2. **Single-stage RL at 64K output length**：反对 multi-stage 渐进扩长（会"unlearn" long-ctx 能力，质量不可逆下降）
  3. **Token-weighted mean loss > sequence-mean loss**（Figure 7 左）—— 收敛快、抑制 length bias
- Infrastructure：**Slime supports both colocated synchronous and disaggregated asynchronous modes**
  - synchronous: math/code/reasoning 用
  - asynchronous: agent / SWE 任务用（rollout 时间长方差大）
- **混合精度 RL**：BF16 训练 + FP8 rollout inference，block-wise FP8 quant 后再 dispatch

## 与 16B 设计的关系

| 维度 | 16B Profile B | GLM-4.5 选择 | 是否值得借鉴 |
|---|---|---|---|
| 深度 vs 宽度 | 27L / 2048（中庸） | 92L / 5120（极深） | **不直接借鉴**（不同量级） |
| Routing | sigmoid + ALF + Ling zero-mean | sigmoid + ALF（不加 zero-mean） | 16B 仍走 Ling 修正 |
| QK-Norm | 是 | 是（仅 4.5 大版） | **GLM 给 16B QK-Norm 一个额外证据** |
| MTP | wind tunnel 待验 | D=1 + λ=0.3→0.1 | GLM 的 **λ 大调度** 是新数据点 — 之前没人给过 0.3 这么高 |
| Optimizer | AdamW (默认) | Muon | **未来 wind tunnel B 候选 add-on** |
| LR Scheduler | WSD | **cosine + 反对 WSD** | **冲突信号** — 详见下面 |
| Aux loss | none (ALF only) | aux λ=0.0001 作 safety guard | GLM 的"超低 aux 作 hard limit"值得考虑 |

### ⚠️ WSD vs Cosine —— GLM-4.5 的反向信号

**16B Profile B 当前用 WSD**（V3 / Ling 2.0 / Moonlight 共识）。但 GLM-4.5 论文明确：
> "Our early experiments showed that models trained with the WSD schedule perform worse on general benchmarks (SimpleQA, MMLU), indicating underfitting in the stable stage."

这是**唯一**公开反对 WSD 的 100B+ 团队。两个解释：
1. **WSD 在 Muon 优化器下表现差**（GLM 同时换了 optimizer 和 scheduler，无法分离）
2. **WSD 在长训练 (23T) 下 stable 阶段太长，underfit 严重**

**对你 16B 的启示**：如果你**坚持 AdamW**，GLM 的反 WSD 信号可能不适用（混淆变量）。如果你**未来要换 Muon**，要重新 wind tunnel WSD vs Cosine。

## 训练系统（论文没明确说，但可推断）

论文里**没有公开 TP/PP/EP/DP 配置**。这是 Z.ai 一直以来的风格（GLM 系列 base report 都偏架构和数据，不公开 infra）。

可推断的下界：
- 92 层 / 355B → PP ≥ 8（每 stage ≤ 12 层，符合 1F1B 推荐范围）
- 160 experts → EP ∈ {8, 16, 32, 40, 160 的约数}，常见 EP=16
- 5120 × 12288 dense FFN → TP=2 最经济

**比较锚定**：V3 论文公开 EP=64 + PP=16 + TP=1 + DualPipe；GLM-4.5 的 stack 类似规模，应该类似配置但 PP 可能更大（92L vs 61L）。

## 设计哲学：ARC（Agentic, Reasoning, Coding）三位一体

论文不像 V3 / K2 那样追求 "general LLM" 路线，而是**显式为三大 down-stream 任务设计**：
- **Agentic** (tool calling, web search): TAU-Bench 70.1%
- **Reasoning** (AIME, GPQA, MATH): AIME 91.0% / GPQA 79.1% / MATH 72.9%
- **Coding** (SWE-bench, repo-level): SWE-bench Verified 64.2%

这是 100B+ 段位**第一次显式 task-specialized 架构** —— 之前模型都是 "general → fine-tune 出特化版本"。GLM-4.5 把 coding/reasoning 偏好直接烧进 base（多 attention heads + 深 stack + 重 MTP + repo-level mid-training）。

⚠️ **副作用**：在传统 base benchmark 上 GLM-4.5 略差于 V3（GSM8K 79.4% vs V3 87.6%，TriviaQA 80.0% vs V3 82.9%）—— 牺牲了通用知识、换了 ARC 三件套。**100B+ 段位是否应该 "general first then specialize" vs "specialize first" 是 open question。**

## Settled vs Open

### Settled（GLM 自身一致的、4.5/4.6/Air 三版都坚持的）
- sigmoid + ALF 是 base 路由
- MTP D=1 + 重 λ schedule
- QK-Norm 在 350B 段位是 net positive
- 96 头 / 5120 hidden（即 Q/KV ratio = 12）经验稳定
- Muon + cosine 路线

### Open（即使 GLM 团队内部也变动）
- QK-Norm 在 100B 段位是否必要（Air = No 给反向证据）
- WSD vs cosine 的因果（混淆了 optimizer）
- routed_scaling_factor 数值（论文未公布）
- 深 > 宽到底在什么规模生效（Air 用 0.72 跟 V3 一样，说明 < 200B 不需要走深）

### 已否决（GLM 团队明确不做）
- WSD scheduler（明确 reject）
- MLA（用 GQA + partial RoPE 替代）
- Aux-loss 主导（仅 0.0001 作 safety）

## 对你 100B-200B 设计的建议

1. **如果做 100-150B 推理型模型** → 复刻 GLM-4.5-Air：46L / 4096 / 128 experts / 8 KV head / **不用 QK-Norm**
2. **如果做 300-400B 高瘦推理型模型** → 复刻 GLM-4.5：92L / 5120 / 160 experts / **必加 QK-Norm**
3. **如果对 Muon 没有把握** → 不要因为 GLM 用就跟（混淆变量太多），先在 wind tunnel B 验证
4. **不要直接 copy GLM 的 cosine schedule** —— 这是 Muon 配 cosine 的耦合结论，不是单独的 cosine 推荐
